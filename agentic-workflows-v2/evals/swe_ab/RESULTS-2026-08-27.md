# SWE-fix A/B — results, 2026-08-27

**Question:** does ARP's multi-step review loop repair more defects than a single
coder call, at equal model and equal input?

**Short answer:** no. The direct arm scored higher on every reading, the accuracy
gap is not statistically significant, and the review loop cost 3.5× the wall
clock to get there. On this case set the loop is not paying for itself.

## Setup

| | |
|---|---|
| Cases | 50, mined from agentic-evalkit's own source, each a verified mutation that makes a named real test fail |
| Arm A | `swe_fix_direct` — 1 step (`tier2_coder`) |
| Arm B | `swe_fix_review_loop` — 5 steps (reviewer → coder → analyzer → coder → tester) |
| Model | `ollama:deepseek-v4-flash:0731-cloud`, pinned to every tier in both arms |
| Temperature / seed | 0.0 / 20260827, attempts=1, concurrency=3 |
| Ground truth | the case's covering pytest file, run against the returned source |
| Judge | present but weight 0.0 — uncalibrated, gates nothing |
| Cost | zero: free Ollama Cloud endpoint, paid credentials deleted from the child env |
| Run ids | A `6826511430f141c495a39c7fe0ae558f`, B `ed558dd120ea4c56aefe2c6a0b82fa98` |

## Headline

| | Arm A (direct) | Arm B (review loop) |
|---|---|---|
| Pass rate, raw | **48/50 = 96.0%** [86.5–98.9] | 45/50 = 90.0% [78.6–95.7] |
| Accuracy where both answered (n=47) | **46/47 = 97.9%** | 45/47 = 95.7% |
| Timeouts | 1 (at 300 s) | 3 (at 420 s) |
| Wall clock | **10.7 min** | 37.0 min |
| Median per case | **12.6 s** | 47.0 s |

## The paired read

Over the 50 shared cases: both solved 45, **only A** solved 3, **only B** solved
0, neither solved 2.

- Difference (B − A): **−6.0%**, 95% bootstrap CI **[−14.0%, +0.0%]**
- McNemar exact **p = 0.25** on 3 discordant pairs
- Restricted to cases where both arms returned a verdict: A-only 1, B-only 0,
  **p = 1.00**

So the direction is consistent — A never lost a case B won, in either reading —
but three discordant pairs cannot carry statistical significance. **The interval
is the result, not the point estimate.**

## What B's losses actually were

| Case | Arm A | Arm B | Real cause |
|---|---|---|---|
| EVK-MUT-008 | pass | timeout | ran out of time, never answered |
| EVK-MUT-037 | pass | timeout | ran out of time, never answered |
| EVK-MUT-010 | pass | fail | genuine wrong repair |
| EVK-MUT-006 | timeout | timeout | both ran out of time |
| EVK-MUT-013 | fail | fail | genuinely hard for this model |

Two of B's three losses are operational, not cognitive — and B had the *more*
generous timeout (420 s vs A's 300 s). Under ADR-0008 those never count as task
failures, which is why the verdict-only row above exists. On correctness alone
the two arms are nearly indistinguishable: 97.9% vs 95.7%, one discordant case.

The review loop's real cost is that four extra model calls per case push a
meaningful fraction of runs past any reasonable deadline.

## What this does not show

**A ceiling effect dominates.** At 96% the case set is too easy to separate two
competent orchestrations. Single-mutation repair, with the defective file inline
and the failing test named, is a task a strong model nails almost every time.
Nothing here says the review loop is useless — it says these cases cannot tell.
To discriminate, the set needs cases the direct arm actually fails: multi-hunk
repairs, multi-file changes, or no failing-test hint.

**One model, one seed, one attempt.** No claim generalises to another model,
and `attempts=1` means per-case outcomes carry sampling noise that pass@1 alone
does not show. Three attempts with pass@1/pass@3 reported side by side would.

**`MUT` cases are not `BF` cases.** All 50 are synthetic mutations. They have
real ground truth — a real test really fails — but a mutation is not the same
distribution as a bug a human actually wrote. Only 6 real `fix(...)` commits in
EvalKit qualify for mining; broadening to EK and ARP is the fix.

**The judge contributed nothing to these numbers**, by design. Its two rubric
criteria (root-cause accuracy, verification specificity) are recorded as
evidence at weight 0.0. Promoting it needs ≥30 good and ≥30 bad labelled cases
and a calibration clearing TNR ≥ 0.95 / TPR ≥ 0.85 on the *Wilson lower bound*,
age ≤ 90 days.

## On the comparison gate

`agentic-evalkit compare` was called on these two reports and refused:

```
[incompatible_runs] runs '68265114...' and 'ed558dd1...' are not comparable:
target name differs: 'arp-swe_fix_direct' != 'arp-swe_fix_review_loop'
```

That is correct behaviour, not an obstacle. `target_name` and
`target_fingerprint` are non-waivable provenance under ADR-0015 because two
different systems are not two versions of one system. The paired analysis above
is the honest substitute. Giving both arms the same target name to satisfy the
gate would have laundered the very difference under measurement.

## Recommendation

1. Keep `swe_fix_direct` as the default for single-file defect repair. It is as
   accurate and 3.5× faster.
2. Do not conclude the review loop is worthless — conclude this case set cannot
   measure it. Build 30–50 harder cases and re-run before deciding.
3. If the loop is re-run as-is, raise its timeout past 420 s or its non-verdicts
   will keep being misread as failures.
4. Run `attempts=3` next time and report pass@1 with pass@3.

Reproduce: `uv run python run_ab.py --arm a` / `--arm b`, then
`uv run python analyze.py`.
